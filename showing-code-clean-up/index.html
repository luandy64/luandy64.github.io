    Showing Code Clean Up

    Page created : 2026-07-16T13:24:38-04:00
    Last updated : 2026-07-16T17:19:37-04:00

    The context of this code is not super important. But here is something I don’t think is talked about a lot: how does code clean up happen.

    (defn solve-all
  ([starting-word]
   (solve-all starting-word (look-down starting-word) [starting-word]))
  ([starting-word stack chains]
   (if (seq stack)
     (let [_ (println "solve-all: START:" starting-word stack chains)
           new-branches (reduce (fn [acc [word _]]
                                  (let [new-chains (solve-all word
                                                             (look-down word)
                                                             [word])
                                        _ (println "new-chains:" new-chains)
                                        ans (-> (concat acc
                                                        (mapv (fn [chain]
                                                                (println "adding" chain)
                                                                (-> [starting-word]
                                                                    (concat chain)
                                                                    vec))
                                                              new-chains))
                                                vec)]
                                    (println "ans:" ans)
                                    ans))
                                []
                                stack)]
       (println "solve-all: END" starting-word new-branches)
       new-branches)
     [chains])))

    I have this recursive function that is littered with print statements to aid in debugging. This is not what I want the final version of the function to look like. I want to show off the intermediate steps because I think there are things to learn on the way.

    So first, removing the print statements is easy and leaves us with

    (defn solve-all
  ([starting-word]
   (solve-all starting-word (look-down starting-word) [starting-word]))
  ([starting-word stack chains]
   (if (seq stack)
     (let [new-branches (reduce (fn [acc [word _]]
                                  (let [new-chains (solve-all word
                                                             (look-down word)

                                        ans (-> (concat acc
                                                        (mapv (fn [chain]
                                                                (-> [starting-word]
                                                                    (concat chain)
                                                                    vec))
                                                              new-chains))
                                                vec)]
                                    ans))
                                []
                                stack)]
       new-branches)

    Next, it doesn’t matter if we work inside-out or outside-in. In this case I’ll just work outside-in. The first thing that jumps out at me is this pattern

    (let [thing (do-things)]
  thing)

    I don’t think naming the return value is all that useful, so in cases like these, I’ll always just lift (do-things) up a level. In emacs, that’s an easy paredit-raise-sexp, which is M-r to me. Doing that twice leaves us with the following

    (defn solve-all
  ([starting-word]
   (solve-all starting-word (look-down starting-word) [starting-word]))
  ([starting-word stack chains]
   (if (seq stack)
     (reduce (fn [acc [word _]]
               (let [new-chains (solve-all word
                                           (look-down word)
                                           [word])
                     ans (-> (concat acc
                                     (mapv (fn [chain]
                                             (-> [starting-word]
                                                 (concat chain)
                                                 vec))
                                           new-chains))
                             vec)]
                 ans))
             []
             stack)
     [chains])))

    Next, ans has the same useless binding problem, so I’ll move that out. This one is a little more manual, I have to kill the value of ans starting from the paren wrapping the thread-first. Then I’ll move out the let’s binding section and paste. And then clean up the naked binding and join the dangling let-] up to the end of the new-chains pair.

    (defn solve-all
  ([starting-word]
   (solve-all starting-word (look-down starting-word) [starting-word]))
  ([starting-word stack chains]
   (if (seq stack)
     (reduce (fn [acc [word _]]

                                           [word])]
                 (-> (concat acc
                             (mapv (fn [chain]
                                     (-> [starting-word]

                                   new-chains))
                     vec)))

    Now the let binding holds just one thing, so it’s pretty questionable if it should stay. This is when I would inline the change and look to see if I like it more.

    (defn solve-all

    This doesn’t look too too bad and because the piece of code I just touched is at the end of the form, my thread-last senses are tingling. And skimming up a level too, the mapv is in the final position of the concat. So it’s time to put my cursor on the concat’s ( and call M-x clojure-thread-last-all.

    (defn solve-all
  ([starting-word]
   (solve-all starting-word (look-down starting-word) [starting-word]))
  ([starting-word stack chains]
   (if (seq stack)
     (reduce (fn [acc [word _]]
               (-> (->> [word]
                        (solve-all word
                                   (look-down word))
                        (mapv (fn [chain]
                                (-> [starting-word]
                                    (concat chain)
                                    vec)))
                        (concat acc))
                   vec))
             []
             stack)
     [chains])))

    Now (-> ... vec) is the same as (->> ... vec), so that’s a quick adjustment to make.

    Not every thread-last is perfect (or thread-first for that matter) and some times I think the code reads better when you combine the first two elements of the thread. This is one of those cases and it’s a quick change to make

    The final change I want to make is a thing happening in 2 places, this pattern of

    (-> (concat thing1 thing2)
    vec)

    This is about taking a vector and combining it with another vector and ensuring you have a vector at the end. This advice comes from Stuart Sierra’s Clojure Don’ts: Concat. Swap a concat with an into, but in this case, drop the vec too.

    (defn solve-all
  ([starting-word]
   (solve-all starting-word (look-down starting-word) [starting-word]))
  ([starting-word stack chains]
   (if (seq stack)
     (reduce (fn [acc [word _]]
               (->> (solve-all word
                               (look-down word)
                               [word])
                    (mapv (fn [chain]
                            (into [starting-word]
                                  chain)))
                    (into acc)))
             []
             stack)
     [chains])))

    Last but not least, The single-arity line is looking a little dense, so I want to break it up with some whitespace.
